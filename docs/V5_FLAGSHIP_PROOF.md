# V5 Flagship Proof & Native Teamwork

Nakeuri Flutter Foundry **5.0.0a1** closes the remaining locally implementable gaps identified after V4. The goal is not to manufacture a larger simulated score. V5 moves the system toward evidence that can support a real flagship claim.

## What changed

1. **Executable Specification Compiler v2** — user-authored requirements are separated from inferred non-functional and negative cases; stable oracle IDs make requirement-to-evidence coverage machine-checkable.
2. **Antigravity-native specialist team** — bootstrap creates workspace agents in `.agents/agents/` with explicit read/write tool boundaries, model tiers and sandbox command policy. Writers cannot approve themselves.
3. **Antigravity headless provider** — LOW/MEDIUM lifecycle tasks can run through the official `agy` headless CLI with native agent selection, JSON output and structured reviewer schemas. It is deliberately not credited as HIGH/RELEASE isolation by itself.
4. **Experimental hardened Kubernetes Job provider** — optional real `kubectl` execution path with non-root pods, dropped capabilities, read-only root filesystem, CPU/memory limits, disabled service-account token and deny-by-default NetworkPolicy. Controller-owned source checkout/upload and result synchronization remain an explicit external gate.
5. **Patrol native E2E adapter** — release verification can execute configured Patrol journeys and bind the result to a runtime evidence artifact.
6. **Defect-to-defense loop** — escaped defects become proposed regression tests, architecture rules, security invariants or contracts; policy-changing defenses need independent verification and human approval before promotion.
7. **Empirical benchmark harness** — every profile receives a fresh clone of the same resolved commit; hidden acceptance commands are withheld from the runner; token/cost budgets are enforced; machine fingerprint and exact source SHA are recorded.
8. **Ablation reporting** — benchmark profiles can represent Foundry components removed or added, allowing measured value/cost deltas rather than assumptions.

## Claim boundary

A V5 implementation PASS means these mechanisms exist and their local deterministic/stress tests pass. It does **not** prove that Nakeuri beats Antigravity, OpenHands, Official Flutter AI, Wingspan, Symphony, or a professional engineering team.

A real superiority claim requires actual runners under the same source commit, tasks, hidden acceptance tests, budgets, machine class and time window, plus real device/provider/release evidence.

## Important hardening controls

- compiler-detected risk can only escalate task risk;
- high-risk preflight occurs before writer implementation;
- architecture/security/test/simplicity review lenses are separated from the writer;
- MCP lifecycle routes through the same unified runtime-provider policy as CLI execution;
- provider self-claims are insufficient for HIGH/RELEASE proof;
- Kubernetes results must report a source commit, but controller-owned source/result transport is not yet implemented end to end;
- scheduler lease fencing prevents stale workers from completing reclaimed tasks;
- terminal dependency failure/cancellation is reconciled through descendants;
- integration drift blocks stale mergeability when the base branch changed overlapping paths;
- hidden benchmark tests are applied only after the agent finishes coding;
- benchmark profile order is balanced and paired significance can be reported.
